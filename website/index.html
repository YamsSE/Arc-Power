Key points

Everything you need to
unlock your Arc GPU

Overclocking

Power limit (W), core frequency offset (MHz), voltage offset and temperature limit (°C) — applied through Intel's documented IGCL API with a warranty-waiver gate on first use.

Extended range

On Alchemist, power limits up to 315 W and temperature limits up to 115 °C via a bundled 2023 IGCL runtime the kernel driver still accepts. Elevation prompt + explicit confirm required.

Expert controls

VRAM frequency and voltage offsets, GPU voltage lock and custom VF curves — capability-gated, so they only appear on hardware that actually exposes them.

Live telemetry

Clocks, temperatures, power from GPU energy counters, fan RPM, utilization and throttle reasons — plus FPS / frame-time via PresentMon and VRAM via DXGI, as readouts and rolling graphs.

Profiles & boot apply

Save, load, rename and delete named profiles, and apply one silently at every logon through an elevated scheduled task — with a safe default fallback.

Safety-first applies

Every value is clamped to the device-reported range, every apply is verified by read-back — including a delayed re-read to catch momentary "lies" — and refusals surface as honest per-control errors.

Fan control

Auto, curve and fixed modes with an interactive SVG curve editor — hover/drag readouts and manual per-point boxes. Unlocked on Alchemist through IGCL speed tables; read-only on boards that don't expose control.

Reversible tweaks

Registry hacks — MPO disable, HAGS and more — with one-click Enable / Disable / Revert, per-step verified writes and honest per-step reporting.

Honesty by design

Overclocking that respects
your hardware

01

Clamped ranges

Values are bounded to the device-reported minimums and maximums in both the UI and the backend. Arc Power never overrides driver-level ceilings.

02

Verified read-backs

Every apply is confirmed by reading the value back from the driver — including a delayed re-read — so a setter that "succeeds" silently never counts as applied.

03

Honest refusals

When the driver refuses, you get a truthful per-control error with a message you can act on — never a silent failure or a fake success state.
